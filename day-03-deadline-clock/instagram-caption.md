## 본문 (복사해서 붙여넣기)

"D-3인 줄 알았는데, 실제로는 6시간." ⏰

공지에 `2026-11-21 18:00 UTC` 라고 적혀 있으면
한국 시각으로는 **11월 22일 새벽 3시**입니다.
달력에 21일이라고 적어 두면, 하루를 그냥 잃습니다.

공개 MCP 두 개를 섞었습니다.
Time MCP(시간대·서머타임) + SQLite MCP(한 파일 저장) → **deadline-clock** (6 tools)

마감을 **날짜가 아니라 '한 순간 + 한 시간대'** 로 저장합니다.
그래서 볼 때마다 그 시간대에서 다시 셉니다.

· 남은 시간 — "1일 8시간 남음" (초 기준, 서머타임이 끼면 벽시계와 1시간 달라짐)
· D-day — 날짜 기준, 자정을 넘기면 D-1 → D-DAY
· 남은 평일 — 월~금만 (공휴일은 모른다고 응답에 적습니다)

입력은 그냥 말하듯이:
`내일 오후 6시` · `3일 뒤 18시` · `다음 주 화요일 오전 10시 30분` · `11/25` · `+90m`

날짜만 주면 그날 23:59:59 로 잡고, **그렇게 가정했다는 사실을 응답에 남깁니다.**
"1/5" 처럼 이미 지난 날짜면 내년으로 넘기고, 그것도 적습니다.

원본에서 가져온 규칙 세 가지 👇
1️⃣ IANA 키는 대소문자까지 구분 — `europe/warsaw` 는 거부하고 `Europe/Warsaw` 를 알려 줍니다
2️⃣ 시계가 되돌아가는 날의 `01:30` 은 **두 번** 있습니다 → 첫 번째로 저장하고 두 번째도 표시
3️⃣ 시계가 앞으로 뛰는 날의 `02:30` 은 **없습니다** → 저장하지 않고 "가장 가까운 03:30"을 제안

버린 것: 임의 SQL 실행(read_query/write_query), create_table, 프롬프트·리소스
가져온 것: 시간대 엄격 판정 + 한 파일 스키마 + 읽기/쓰기 분리

## 대체 텍스트(alt text, 선택)

Time MCP와 SQLite MCP를 섞어 만든 deadline-clock MCP 소개 릴스. UTC로 공지된 마감이 한국
시간으로 다음 날 새벽 3시가 되는 예, 남은 시간·D-day·평일 계산, 서머타임으로 시각이 두 번
있거나 아예 없는 경우를 보여 줍니다.
