# 인스타 캡션 — Day 10 · test-radar

## 본문 (복사용)

커밋 하나 바꿨는데 **테스트 300개**를 다 돌렸습니다. **8초.**

바꾼 건 두 파일, **+15줄 / -1줄**. 그 8초를 매번 버리고 있었습니다.

테스트를 골라 돌리는 건 원래 어렵습니다
· **어디까지가 영향인지** — import 를 따라가야 압니다. 손으로 하면 빠뜨립니다
· **빠뜨리면 더 비쌈** — 시간 아끼려다 회귀를 놓치면 그게 제일 큰 손해입니다
· **"같은 폴더니까"** — 이건 근거가 아니라 추측입니다
· **동적 import** — `importlib.import_module`, 변수 `require` 는 그래프에 선이 안 그려집니다
· **conftest 하나** — fixture 를 건드리면 어느 테스트가 영향받는지 정적으로 알 수 없습니다

그래서 이렇게 고릅니다
**근거 4단계** — ①테스트 자신 ②바뀐 심볼을 직접 import/문자열 참조 ③2단계 안의 전이 import
④같은 디렉터리(참고용, 필수 아님). **같은 폴더라는 이유만으로는 안 고릅니다.**
**확신 없으면 전체** — 설정 변경 · 파싱 실패 · 동적 import · 선택 60% 초과면 `판정: 전체 실행`.
**실행은 안 함** — 읽기 전용입니다. pytest 명령은 문자열로만 만듭니다.

실제로 돌려 봤습니다.

**flask 실제 커밋 (`de8429ff`, IPv6 세션 수정, 2파일 +15/-1)**
· 테스트 27파일 중 **6파일 · 391항목 → 159항목 (41%)** · 위험 규칙 0 · `판정: 선택 실행`
· 수정을 되돌린 사본에서: **선택한 6파일 → 회귀 테스트 실패 (1.14초)**,
  전체 485개 → 같은 테스트가 실패 (**3.38초**)
· 빠뜨리지 않았고, 1/3 시간에 같은 결론

**flask 릴리스 diff (`3.0.2 → 3.0.3`, 44파일 +754/-634)**
· 선택 22파일 / 358항목 (93%) → **`판정: 전체 실행`**
· `pyproject.toml`·`tox.ini` 가 바뀌었으니 이건 줄이는 게 아니라 전체를 돌려야 합니다. 도구가 그렇게 말합니다

**변이 시험 (day-09 `log-triage`, 테스트 304개)**
· 소스에 변이 5개 → **선택한 테스트가 4개를 잡음**
· 선택은 놓치고 전체가 잡은 것: **0개**
· 전체도 못 잡은 것: **1개** (서명 공백 처리 — 테스트가 그 동작을 안 봅니다. 선택 실패가 아닙니다)
· 공용 모듈 변이는 **3파일/80항목(2.65초)** 만으로 잡혔습니다 (전체 9.42초)

오늘의 조합
· **codebase-memory-mcp** (MIT · ★49,168) — diff 를 심볼에 매핑해 **테스트 영향**을 내고,
  증거가 부족하면 **넓게 돌리는** Smart CI 태도
· **github-mcp-server** (MIT · ★34,757 · 툴 96개/툴셋 23개) — **범위를 좁혀 읽기**,
  `--read-only` 기본, 결과는 작은 DTO 로
둘 다 원본 코드는 한 줄도 복사하지 않았습니다. 설계와 태도만 가져와 **툴 10개 · 규칙 23종**으로 다시 썼습니다.

test-radar 가 지키는 것
· **근거 없는 선택 없음** — 같은 디렉터리·비슷한 이름은 '참고'에만
· **확신 없으면 전체** — 6가지 폴백 조건을 통과해야 선택 실행이 됩니다
· **읽기 전용** — 저장소를 고치지 않고, 명령을 실행하지 않습니다
· **모르는 건 모른다고** — 커버리지·실행 시간·테스트 통과 여부는 판정하지 않는다고 결과에 씁니다

검증한 것
· 테스트 **308개** (diff 39 · Python 43 · JS 28 · 그래프 42 · 선택 37 · 규칙 38 · 계획·보고 28 ·
  CLI 16 · 저장소 8 · MCP 29 — in-memory + stdio 서브프로세스)
· 예제 저장소(13파일)는 실제 pytest 로 `7 passed, 1 skipped`
· 변이 5개 실측은 `tools/probe.py` 로 다시 돌릴 수 있습니다

정직하게: **테스트가 통과하는지**는 판정하지 않습니다. 실행 시간은 항목 수 × 가정값 **모델**입니다.
커버리지 %, 동적 import 뒤의 간선, 같은 이름의 다른 심볼, JS 재export 체인은 못 봅니다.
그리고 선택이 항목을 1/3로 줄여도 **무거운 통합 테스트 하나**가 들어오면 시간은 안 줄어듭니다 —
그래서 그런 파일을 `broad-test` 로 표시합니다.
