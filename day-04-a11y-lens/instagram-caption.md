# 인스타 캡션 — Day 04 · a11y-lens

## 본문 (복사용)

alt 하나 빼먹은 페이지가 화면 낭독기에서는 51건이 안 보이는 페이지가 됩니다.

W3C 접근성 데모 'Inaccessible' 페이지를 돌려 봤더니 — 브라우저 없이, 파일만으로 0.1초에 51건. 고친 'Accessible' 페이지는 96점. (남은 1건은 main 랜드마크, 사실과 맞는 지적이었습니다.)

오늘의 조합
· Chrome DevTools MCP 의 `a11y-debugging` 스킬 — 검사 항목과 순서
· Playwright MCP — 접근성 스냅샷 + `ref` + depth
둘 다 Apache-2.0, 코드는 복사하지 않고 설계만 가져와 7개 툴로 다시 만들었습니다.

a11y-lens 가 하는 일
1. HTML → 접근성 트리 (`ref=e12` · 원본 줄 번호 L18)
2. 규칙 20종 (WCAG 2.2 A·AA) — 이미지 alt, 버튼 이름, 레이블, 제목 단계, aria-hidden 안의 포커스, 확대 금지 viewport …
3. 고치는 순서 + 바꿀 마크업
4. 고친 뒤 `verify` — 없어짐/남음/새로 생김을 지문으로 비교

브라우저 기반 도구와 다른 점은 딱 하나, **줄 번호를 줄 수 있다**는 것. 대신 색 대비·터치 크기·키보드 순서는 판정하지 않습니다. 그건 레이아웃을 그려 봐야 알 수 있어서, 브라우저 도구의 몫으로 남겼고 README 에도 그렇게 적었습니다.
